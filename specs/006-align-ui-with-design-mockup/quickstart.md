# Quickstart: Validating the UI Design Alignment

This is a validation guide, not a build guide — it proves the restyle in
`research.md`'s drift list was applied correctly and nothing else regressed.
Full implementation steps live in `tasks.md` (generated by `/speckit-tasks`).

## Prerequisites

- Dependencies installed (`npm install`, already done in this repo).
- No `VITE_API_BASE_URL` set, so the app runs against the mock clients
  (`templateClient.mock.ts`, `templateDetailClient.mock.ts`) — no backend
  needed for this visual check.

## 1. Run the automated regression suite

```bash
npm run lint
npm run build
npm run test -- --run
```

Expected: all three pass with zero errors, confirming FR-007 (no functional
regression) and Constitution Principle V.

## 2. Start the app and the design reference side by side

```bash
npm run dev
```

Open the printed local URL (e.g. `http://localhost:5173/`) in one browser tab,
and open `docs/design/how2prompt-workspace-mockup.html` directly (no build step
needed) in another tab, or via `file://` in a headless browser for automated
screenshot diffing.

## 3. Catalog page (User Story 1 / SC-001)

1. On the mockup, click "Tiếp tục với vai trò Khách →" to reach the catalog
   view.
2. Compare against the app's `/` route:
   - The "Chính thức" badge on any official template card must render in
     mixed case (not `CHÍNH THỨC`) with `--accent-soft` background / `--accent`
     text (research.md drift #1).
   - Search box, filter chips, model selector, Featured/Trending rails, and the
     full grid must match the mockup's spacing and colors (already aligned per
     research.md — this step is a regression check, not expected to find new
     issues).
3. Toggle the OS/browser color scheme to dark and repeat — every element must
   resolve to the token table's dark-column values.

## 4. Template detail page (User Story 2 / SC-002)

1. Click any template card to open its detail page (e.g.
   `/templates/debug-loi-hieu-qua` in the mock data).
2. Verify:
   - `← Quay lại thư viện` back-link renders in monospace, underlined, at
     `0.8rem` (research.md drift #4).
   - The official badge (if present) is not forced uppercase (drift #1).
   - The favorite button's active/hover red is `#C23A2E` in light theme, not
     `#C23A2A` (drift #2) — inspect via devtools computed style or a color
     picker on the screenshot.
   - "Hướng dẫn sử dụng" and "Ví dụ kết quả" cards use a `14px` border radius
     and `1.1rem 1.2rem` padding, matching the template card / output-box
     language (drift #5).
   - The usage-count text renders at `0.7rem` (drift #6).
3. Repeat in dark theme.

## 5. Shared top navigation bar (User Story 3 / SC-003)

1. While signed out, confirm the "Đăng nhập" link and nav items ("Thư viện",
   "Lịch sử") render per the mono/underline link convention.
2. Hover "Thư viện"/"Lịch sử": a bottom border in `--ink-faint` must appear
   (research.md drift #3) — currently missing, so this is the primary thing to
   re-check after the fix.
3. Sign in (mock auth) and confirm the signed-in state (avatar initial, name,
   "Hồ sơ", "Đăng xuất") still matches, in both themes.

## Pass criteria

All of SC-001 through SC-004 in `spec.md` hold: zero visual discrepancy on the
two content screens, the topbar matches in both auth states, and 100% of the
existing automated tests still pass.
